# Live Windows file clipboard validation

Validated 2026-09-10 with generated local data. The ignored native test publishes
through the production Windows clipboard service and disk-backed transfer catalog.
An independent .NET consumer obtains the actual OLE `IDataObject`, decodes
`FileGroupDescriptorW`, and reads indexed `FileContents` streams in 32 KiB chunks.
It then publishes a real `CF_HDROP` file list, which the production native input
service decodes. No remote host is contacted.

This is native OS-format interoperability, not a new Explorer UI, live SFTP,
network-interruption or Finder test. Historical actual Explorer and live SFTP
file/folder tests are recorded in [system clipboard](system-clipboard.md).
The separate 91-check installed-app fixture proves SDK/frame/broker integration
using injected clipboard services; [app clipboard](app-clipboard.md) states that
boundary. Together these check the current Windows contract at its layers.
Single-item Cut reservations have their own native and installed-app tests;
this probe exchanges copies and does not test deletion or cut semantics.

## Repeat explicitly

Build the native test executable without running it:

```powershell
cargo test -p shellcanvas --lib --no-run --message-format=json | Out-File -Encoding utf8 .local/file-clipboard-build.jsonl
```

Check the final JSON `build-finished.success` value; a PowerShell pipeline's exit
status alone is insufficient. The runner also requires that successful record.
After approval to replace the clipboard, run:

```powershell
powershell.exe -NoProfile -STA -File scripts/probe-live-file-clipboard.ps1 -AllowClipboardReplacement
```

The runner refuses to run without opt-in. It rejects unsupported original
formats before publication, keeps supported snapshot contents in memory, and
restores only while its unique generated selection still owns the clipboard.
Another application may replace the clipboard; that newer value is left alone.
AnyDesk may synchronize the temporary files. Its private metadata cannot be
restored. Files and logs stay in a unique directory below `.local/live-file-clipboard`
for inspection. This test is excluded from ordinary verification and never
replaces the normal desktop executable.
